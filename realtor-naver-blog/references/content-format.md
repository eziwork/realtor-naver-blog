# 원고와 이미지

확정 전략의 질문 순서대로 구성한다. 유형별 고정 챕터, 전체 문장 수, 키워드 반복 횟수는 없다. 사용자가 직접 정한 말투·배치를 우선한다. 기본은 짧은 한 문장씩, 전체 가운데 정렬, 문장 사이 빈 줄 한 줄이다. 저장 문체가 이 규칙과 충돌하면 충돌하는 부분을 따르지 않는다.

Codex가 post.json을 작성하면 workflow.mjs prepare가 blog-post.md, transfer.html, manifest.json을 생성한다. 수정은 post.json부터 하고 다시 prepare한다. 이후 이미지·프로필·원고가 바뀌면 begin이 거부한다. 필드는 [workflow-contract.md](workflow-contract.md)를 참조한다.

- 제목·도입: 주 타겟의 검색 질문과 확인된 조건. 확정된 title_direction과 intro_direction을 따른다.
- 문단/소제목: section_id로 전략의 문단에 연결한다. 사실 문장은 fact_ids에 근거를 연결한다. 없는 공간이나 시설 챕터를 만들지 않는다.
- 조건표: 2열 표, 확인된 사실만. 원문이 '면적 31평'이면 전용/공급 중 하나로 단정하지 않는다. 수치 변환은 계산 근거를 사실에 추가한 후 사용한다.
- 사진: **기본은 받은 사진 전부 싣기**다(Dr-Min 07f10ef: 폴더째 줬으면 다 실으라는 뜻). 실제 파일을 열어 분류하고 설명 문단 옆에 배치한다. 비슷한 구도라는 이유만으로 빼지 않는다. 뺄 수 있는 것은 완전 중복·흔들림·매물과 무관한 사진뿐이며 각 이유를 excluded_photos에 기록하고 보고한다. 사용자가 장수를 정하면 그 지시가 우선한다. 수집 실패는 제외 사유로 감추지 않고 따로 보고한다.
- 썸네일: **1:1 비율**, 매물명·검증된 후킹·사무소(또는 중개사) 이름을 글자로 넣는다. 읽을 수 있는 글자 크기로 만든다.
- 상담 배너: **한 번 만들어 재사용한다.** `~/.codex/naver-realtor-blog/assets/cta-banner.png`가 있으면 글자를 실제로 읽어 현재 사무소명·연락처와 같을 때 그대로 쓰고, 다르거나 없을 때만 새로 만들어 그 위치에 저장한다. 공용 자산 폴더에 쓸 수 없으면 배너를 run 폴더에 저장하고 그 경로를 쓴다 — 막혔다고 배너를 포기하지 않는다(Dr-Min). 배너에는 전화번호를 크게 넣는다(전화 링크가 사라져도 번호가 보이게). 현재 사무소명/등록 연락처와 육안 대조. office_hash는 생성 시 전체 office 객체 해시. 해시 일치만으로 이미지 글자를 검증했다고 주장하지 않는다.
- 지도: 확인된 장소만. 주소/지도 장소를 확정 못 하면 삽입하지 않고 map_omission_reason에 이유를 남긴다. 근처 역을 매물의 정확한 위치처럼 쓰지 않는다.
- CTA: 공간 배치·이전 일정·방문 예약 등 고객이 상담에서 얻을 가치를 구체화한다. 고객의 업종·차량 규모·희망 일정은 물을 수 있지만, Codex가 매물 정보를 모른다는 설명이나 미확인 목록을 상담 문구로 옮기지 않는다. 아직 확인되지 않은 결과를 보장하지 않는다.
- cta.text에는 연락처를 중복 입력하지 않는다. 렌더러가 프로필 연락처 한 줄을 붙인다. 배너에는 번호를 표시한다.
- 태그: 끝의 해시태그 한 줄, 별도 '태그' 소제목 없음. 매물에 없는 지명·평수·시설을 검색어/태그에 넣지 않는다.

## 문체

프로필 YAML은 유지하고 같은 폴더의 blog-styles.json에 블로그 ID별로 저장한다. URL/ID 정규화, 최대 5개 출처, 표본 부족 여부는 코드가 검증한다. 스타일 추론은 Codex가 한다.

매물을 잘 이해한 중개사가 고객과 이야기하듯 친숙한 존댓말로 설명한다. '입니다·있어요·좋아요'를 문맥에 맞게 쓰되 과장이나 지나친 감탄은 피한다. 주거는 생활 용어로 비용과 공간을 설명한다. 사업용·토지의 전문용어는 필요한 경우만 쓰고 바로 쉬운 말로 풀어준다.

- 확인된 사실은 바로 말한다. '군자역까지 도보 9분으로 표시됩니다' 대신 '군자역까지 도보 9분입니다.'라고 쓴다. 도보 시간의 출처가 필요하면 별도 짧은 문장으로 '도보 시간은 네이버 기준입니다.'라고 덧붙인다.
- '확인할 수 있습니다·보입니다·살펴볼 수 있습니다·표시됩니다'를 습관적으로 반복하지 않는다. 근거가 충분하면 '위층에도 세면대가 있어요.'처럼 공간과 쓰임을 직접 설명한다.
- 독자용 문장과 캡션에 '사용자 제공·등록사진·사진 관찰·fact_ids' 같은 작업 용어를 넣지 않는다. 출처 연결과 검수 설명은 facts.json·검수 기록에 보관한다. 사진 설명은 '아래층 화장실입니다.'처럼 편하게 쓴다.
- 어려운 계약 표현과 불필요한 주의 문장을 줄인다. 가구 포함 여부·층고·상부 공간 면적·법적 용도처럼 원고에 필요한 정보가 없으면 작성 전에 스킬 사용자에게 Codex 질문으로 확인한다. 답이 없으면 해당 내용을 제외하며 '따로 확인해야 해요' 같은 문장으로 대신 채우지 않는다.
- 고객용 글에는 확인된 사실만 친숙하고 직접적으로 설명한다. '모르겠습니다·미확인입니다·확인이 필요해요·안내 내용이 서로 달라요'처럼 수집 상태를 드러내지 않는다. '약'을 붙여 추측을 사실로 바꾸지 않는다. 누락·충돌·제외 이유는 facts.json·strategy.json·검수 기록과 사용자 보고에 남긴다. 확인된 중요한 제한 조건은 그대로 전달하고, 미확인 내용을 빼면서 사용 가능·허가·적법성 등을 암시하지 않는다.
- 사진만 보고 직접 방문·실측·거래한 것처럼 말하지 않는다. 직접 설명하는 말투와 실제 방문 경험은 별개다.

## 가운데 정렬과 문장 간격

1. 본문 paragraph 블록과 cta.text는 각각 짧은 한 문장으로 작성한다. 여러 문장을 한 블록에 넣지 않는다. 추가 설명은 별도 paragraph 블록으로 나눈다. 숫자·날짜·URL의 마침표를 기준으로 문장을 자동 분리하지 않는다.
2. 각 문장 뒤에 빈 줄 한 줄을 둔다. Markdown 원고는 문단 사이 빈 줄 한 줄, transfer.html은 가운데 정렬한 문단 뒤에 실제 `<p style="text-align: center"><br></p>` 하나를 넣는다. CSS 여백만으로 빈 줄을 대신하지 않는다.
3. 소제목·본문·사진 설명·CTA·연락처·해시태그와 표 안의 글을 가운데 정렬한다. 표의 행·셀 안에는 간격용 빈 문단을 넣지 않는다. 제목은 본문과 별도 입력하며 편집기가 지원하면 가운데 정렬한다.
4. 사진 캡션은 편집기에 따로 넣더라도 동일한 가운데 정렬을 적용한다. 빈 줄이 사진이나 지도 자리 교체 과정에서 사라지거나 두 번 생기지 않게 확인한다.
5. 로컬 HTML만 확인하고 끝내지 않는다. 네이버에 붙여넣은 뒤와 저장본 재열람에서 정렬·문장 사이 한 줄 간격을 확인한다. 보존되지 않으면 편집기의 정렬·문단 기능으로 고친다.

읽은 글의 방문·직접 거래·고객 후기 표현을 새 원고로 복제하지 않는다. 문체만 저장하며 기존 글의 매물 사실을 새로운 사실 근거로 사용하지 않는다.
